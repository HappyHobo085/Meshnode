# Tauri Management UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Android placeholder page with a full, polished management UI (Svelte) shared by the Android app and a new desktop Tauri app, both talking to the node through one shared Rust command layer.

**Architecture:** `crates/mesh-ui` defines DTOs (exported to TS with ts-rs), `UiError`, an `AdminTransport` trait (pipe/socket on desktop, in-process on Android) and the command logic; its `tauri` feature adds `#[tauri::command]` wrappers. `apps/ui` is the Svelte 5 + Vite + TS frontend built to `apps/ui/dist`. `apps/desktop/src-tauri` (new, own workspace) and `apps/android/src-tauri` (existing) register the shared commands plus platform extras.

**Tech Stack:** Rust 2024 (workspace), Tauri 2 (tauri-cli 2.12.4), Svelte 5, Vite, TypeScript, Vitest + @testing-library/svelte, ts-rs, qrcode, tauri-plugin-dialog / -opener / -barcode-scanner, Kotlin (Android plugin).

**Spec:** `docs/superpowers/specs/2026-11-11-tauri-ui-design.md` (master: `docs/superpowers/specs/2026-11-08-meshnode-design.md` §9, §14 row 6).

## Review Focus

1. **The daemon dies or restarts while the UI is open** (desktop service restarted, `meshd run` killed, Android node stopped): the UI shows the banner within one poll, recovers by itself when the daemon is back (re-locates on `DaemonUnreachable`), and never needs an app restart. Tests: Task 5 `locator_relocates_after_daemon_restart`; Task 6 `poller_shows_banner_then_recovers`.
2. **Invite input is messy**: pasted with spaces/newlines, or a QR that holds something that is not a ticket. Expected: trimmed; a non-ticket gives a readable "That isn't a Meshnode invite" error, not a raw parse message. Tests: Task 2 `join_trims_ticket_whitespace`, `join_non_ticket_is_invalid_argument_with_hint`.
3. **Large or odd data**: 50 members, 30-character names, emoji or one-letter names, 20 tags. Expected: monograms are 1–2 grapheme clusters, cards and chips wrap/ellipsise without overflowing at 360 px. Tests: Task 7 `monogram_handles_emoji_and_short_names`, `home_renders_fifty_members`.
4. **Deploying a real-world folder**: nested dirs, non-ASCII names, Windows `\` separators, a file over the limit, an empty folder. Expected: paths become `/`-separated relative paths; a refusal names the file. Tests: Task 4 `dir_source_*`.
5. **Streams outlive their page**: leaving Logs, hiding the window, or backgrounding the phone with a follow/probe open. Expected: the stream task ends and its admin connection closes; no more than 4 streams. Tests: Task 3 `stream_ends_when_receiver_dropped`, `fifth_stream_is_refused`; Task 9 `logs_view_cancels_on_unmount`.
