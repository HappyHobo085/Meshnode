# Node Core (sub-spec 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `mesh-core`: a `Node` that creates or joins a mesh over iroh, replicates every op to every member over per-peer `sync/1` sessions, enforces membership, removes members, re-bootstraps when stale, and fetches blobs; plus the store and proto changes the spec requires and a `meshdev` demo example.

**Architecture:** A supervisor (`node`) owns an iroh `Endpoint` + `Router`, a `PeerManager` with one task per effective member, and a reactor on the store's change events. Each peer task runs one `sync/1` session (rounds + live push driven by `diff_since(known)`) over a single bidirectional stream; the session is written against generic `AsyncRead`/`AsyncWrite` so it is tested over `tokio::io::duplex` without iroh. All store calls go through `spawn_blocking`.

**Tech Stack:** Rust 2024 (MSRV 1.90), tokio, iroh 1.4, iroh-blobs 0.104, redb 4 (through `mesh-store`), postcard, blake3, ed25519-dalek 3, tracing, thiserror, proptest/tempfile in tests.

**Spec:** `docs/superpowers/specs/2026-11-09-node-core-design.md` (read it first; section numbers below refer to it). Also read `docs/superpowers/specs/2026-11-09-store-hlc-proto-design.md` §4–§5 and `docs/superpowers/notes/2026-11-09-sub-spec-1-handoff.md`.

## Global Constraints

- Workspace: `edition = "2024"`, `rust-version = "1.90"`; new deps go in `[workspace.dependencies]` and are referenced with `.workspace = true`.
- Every task ends with `cargo test --workspace --all-features`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, and `cargo fmt --all --check` passing.
- Git in this repo needs `git -c safe.directory=D:/AI_Apps/Meshnode`; work on branch `feat/node-core`. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Every `Store` method call from async code goes through `StoreHandle` (`spawn_blocking`). Never call `Store` from an `Acceptor::judge`.
- ALPNs: `b"meshnode/sync/1"`, `b"meshnode/join/1"`, plus iroh-blobs' `iroh_blobs::ALPN`. No iroh-gossip.
- Close codes: `NOT_MEMBER = 1`, `REMOVED = 2`, `PROTOCOL = 3`, `SHUTDOWN = 4`.
- `MeshId = blake3("meshnode/mesh/1" ‖ founder[32] ‖ nonce[32])`.
- Sync frames: `u32` BE length + `mesh_proto::encode(SyncMsg)`, max frame `1 MiB + 1 KiB` (1_049_600). Join frames: same framing, max 256 KiB (262_144).
- Receive limits on `SyncMsg::Ops`: > 256 ops → violation; > 1 MiB summed encoded op size → violation **only when the message has more than one op** (`batch_ops` puts an oversized single op in its own batch).
- Default timings: sync interval 60 s, silence 60 s, backoff 1 s → 300 s doubling, `retry_pending` 60 s, `compact` 1 h, `gc` 24 h, invite prune 1 h, default invite TTL 15 min.
- `_mesh` names: sets `members`, `removed`, `consumed_invites`; registers `info/<hex>`, `addr/<hex>`; `<hex>` = 64 lower-case hex chars of the NodeId. Role byte: `0` host, `1` client.
- Logs through `tracing`; no `println!` outside `examples/`.

## Review Focus

1. **A maximum-size op** (1 MiB value, 512-byte key, 64-byte order) must replicate: its one-op batch exceeds the 1 MiB batch budget, and its frame is ~1 MiB + 800 B. Expect it applied on the peer, not a `PROTOCOL` close. Test: Task 7 `max_size_op_replicates`.
2. **A connection that drops mid-round** (during diff streaming) must not call `mark_full_sync`, and a later round must complete normally. Test: Task 7 `drop_mid_round_does_not_mark_sync`.
3. **The same data dir opened twice** (a second `Node::open` while one runs) must return a clean `NodeError` (redb "already open" → `Store(Io)`), with no panic and no damage to the running node. Test: Task 8 `second_open_of_same_dir_errors`.
4. **A ticket whose `inviter` bytes don't decode** as an `EndpointAddr` must fail `join` with `NodeError::Proto`, writing nothing. Test: Task 9 `undecodable_inviter_addr_errors`.
5. **`shutdown()` with live sessions** must return within 5 s, and reopening the same dir must work. Test: Task 8 `shutdown_with_peers_is_prompt`.

**Files:**

  - `pub(crate) async fn run_session<R, W>(ctx: SessionCtx, r: R, w: W, dialer: bool) -> SessionEnd` where `R: AsyncRead + Unpin + Send`, `W: AsyncWrite + Unpin + Send`.
  - `pub(crate) enum SessionEnd { Closed, Protocol(String), Store(StoreError), Stale }`.
  - `pub(crate) struct PeerMetrics` (atomics/mutex): `rtt_ms`, `last_seen_ms`, `lag: u64`, `rounds_completed: u64`.

Behaviour (spec §6.3–§6.6), in brief:
- One reader task and one writer loop joined with `tokio::select!`; outgoing frames go through one writer (an `mpsc` to the writer is fine).
- `dialer == true` starts a round on entry and every `sync_interval`; either side starts on `StartRound`; the receiver starts one when a message arrives after more than `timings.silence` without one.
- Before starting a round, if `store.is_stale()` return `SessionEnd::Stale` (the node runs §7). When `serve_paused` is set, do not send diffs (live or round) — used while the node decides to re-bootstrap.
- Diffs: `diff_since(known, 256)`; split ops into messages with `mesh_proto::batch_ops`; send `Covered` items as their own messages; raise `known` for each item sent; loop until a page is empty.
- Receive `Ops`: check limits (Global Constraints), `apply_batch`, raise `known`. Receive `Covered`: `apply_covered(origin, upto, advertised.get(origin), acc)`. `Hello` with another mesh, decode error, oversized frame, or over-limit batch → `SessionEnd::Protocol`.
- Round complete (sent `Done` and received `Done`): `mark_full_sync(advertised.get(me))`, `rounds_completed += 1`, emit `RoundComplete(peer)`.
- `lag` = Σ `max(0, own_vv[o] − known[o])`, recomputed after each send/receive batch.
